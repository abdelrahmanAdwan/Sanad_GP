# Session protocol

Every Claude session starts with `/start` and ends with `/handoff`. In Claude Code these are project skills in `.claude/skills/`. In the Claude app, paste the steps below.

## Three layers of memory

| Layer | Files | Written by | Changes |
| --- | --- | --- | --- |
| Project understanding | `CLAUDE.md`, `docs/ARCHITECTURE.md`, `src/*/README.md`, `docs/decisions/` | anyone, by pull request | rarely |
| Personal progress | `sessions/<name>/CURRENT.md` | that person and their Claude only | every session |
| Team status | `STATE.md` | nobody: generated by `scripts/gen_state.py` | every run |

No two people ever write the same file, so the memory never conflicts.

## Set up once per person
1. `cp CLAUDE.local.md.example CLAUDE.local.md` and fill in your name and track. It is gitignored and makes Claude Code load your memory file automatically.
2. `cp -r sessions/_template sessions/<name>` (lowercase, no spaces) if your folder does not exist.

## /start
1. Read `CLAUDE.md`.
2. `git fetch origin`, then `python scripts/gen_state.py --ref origin/main` and read `STATE.md`.
3. Read `sessions/<name>/CURRENT.md` and the GitHub issue it names.
4. Read `docs/ARCHITECTURE.md` and the `README.md` of the module you work on. Nothing else unless needed.
5. **What changed since last time:** compare `main_seen` in your session file with `origin/main`: `git log --oneline <main_seen>..origin/main` and `git diff --stat <main_seen> origin/main`. Note new or changed decision records and changes to `data/schema/`.
6. Report in five lines or fewer: where you stopped, what changed for others that affects you, the next step. Wait for the user to confirm before working.

## /handoff
1. Rewrite `sessions/<name>/CURRENT.md` (one page). Move the previous version to `sessions/<name>/log/<date>.md`.
2. Set `main_seen` to the `origin/main` commit you read at `/start` (or after pulling `main`).
3. Record any new decision as a new file in `docs/decisions/` with `status: proposed` or `open`.
4. Commit on your branch and push.
5. Write a three-part comment on your issue: `Done: … | Next: … | Blocked: …`.
6. Never edit `STATE.md`, another person's files, or files outside your track unless the task requires it.

## Size discipline
Claude cannot read everything each session. Summaries first, details on demand: `CURRENT.md` and `STATE.md` are one page each, `ARCHITECTURE.md` stays short, logs are read only when needed.
